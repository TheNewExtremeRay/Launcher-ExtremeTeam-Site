SECTION 01

What it is

FractalLauncher v1.2.3 ("Microsoft Patch") is a feature-rich custom Minecraft launcher for Windows. Its backend is a Python package (launcher/) and its UI is a single self-contained 119 KB HTML file (assets/ui.html) rendered inside a native window by pywebview (Microsoft Edge WebView2). The Python and JavaScript sides talk over pywebview's js_api bridge: JS calls a 61-method API object, and Python pushes events back as DOM CustomEvents.

Feature highlights:

  • Vanilla + all mod loaders — Fabric, Forge, Quilt, NeoForge (installer jars fetched & run automatically)
  • Microsoft login — full Xbox OAuth2 flow (authorization-code + PKCE, Prism Launcher's public Azure client ID)
  • Offline mode — with a full local Yggdrasil / authlib-injector skin server so offline skins actually work
  • Multiple profiles & accounts — each profile owns its version, loader, RAM, JVM args, game dir, resolution
  • 3D skin viewer — skinview3d (three.js) with cape support and 25 cape presets
  • Modrinth browser — search/install mods, shaders and resource packs with dependency resolution and update checks
  • Servers — curated server list + custom servers with real Server-List-Ping latency checks
  • Screenshots editor, backups, diagnostics, console — canvas crop/blur/draw; zip backups of saves; Mesa3D opengl32.dll conflict detector
  • AI-generated themes — type a description, a Cerebras LLM invents a palette
  • 7 languages — en, fr, es, pt, de + novelty Pirate & Darija
  • Performance tuning baked in — Aikar's G1GC flag set, ABOVE_NORMAL process priority, pre-launch asset cache audit, shipped mod-config presets

⚠ Architectural note: an older CustomTkinter desktop UI used to exist as launcher/app.py, but that file is gone. Every fallback path in main.py, bootstrap.py and pyoxidizer.bzl that references launcher.app is dead code that would crash if ever executed. The webview UI is the only real UI.

SECTION 03

launcher/ — the core package

3.1 webview_bridge.py (1,518 lines) — the JS↔Python API

class API (line 65) is exposed to JavaScript as window.pywebview.api and has 61 public methods. Every method is synchronous (pywebview marshals calls onto worker threads) and follows one return convention:

# success
{ "ok": True,  ...payload }

# failure
{ "ok": False, "error": msg }

Bridge mechanics

  • JS → Python: the UI never touches pywebview.api directly; it caches the handle on pywebviewready and funnels everything through a generic dispatcher: 
    async function call(method, ...args) {
  const api = getApi();
  if (!api) return { ok: false, error: 'API not ready' };
  try { return await api[method](...args); } catch (e) { ... }
}
    56 of the 61 methods are invoked this way from ui.html.
  • Python → JS: a single mechanism — _push(event, data) (line 94) calls window.evaluate_js("window.dispatchEvent(new CustomEvent(...))"). This is the only evaluate_js usage in the entire codebase.
  • Async → sync adapters: callback-style backend functions are converted into blocking returns using threading.Event with timeouts (search 25 s, mod install 10 s, download up to 60 s).
  • Path safety: _safe_path() (line 20) does basename + os.path.realpath prefix checks for every file-delete/edit operation.

3.2 game.py (1,135 lines) — install & launch engine

  • Downloads: fully delegated to minecraft-launcher-lib (SHA-1 verified, internal ThreadPool). This module adds a global requests.Session retry monkey-patch (_install_requests_retry, line 17 — 5× exponential backoff, because mll's stream=True breaks mid-iteration where request-level patching can't help), a 5-minute version-manifest cache, 3-attempt retries on install_version / install_mod_loader, and check_assets_cache() (line 240) — a pre-launch cache audit (merges inheritsFrom parents, respects library rules, dedupes asset hashes) that drives the "Shared cache" UI.
  • build_launch_options() (line 908):
    • -Xmx = -Xms = profile RAM (heap never grows)
    • Full Aikar's G1GC flag set: +UseG1GC, +DisableExplicitGC, +AlwaysPreTouch, G1NewSizePercent=30, G1MaxNewSizePercent=40, G1HeapRegionSize=16M, G1ReservePercent=20, G1HeapWastePercent=5, G1MixedGCCountTarget=4, MaxGCPauseMillis=200, InitiatingHeapOccupancyPercent=15, G1MixedGCLiveThresholdPercent=90, G1RSetUpdatingPauseTimePercent=5, SurvivorRatio=32, +PerfDisableSharedMem, MaxTenuringThreshold=1 + string dedup / OptimizeStringConcat / compressedOops
    • LWJGL software-OpenGL fallback & FML ignore-cert flags (prevents old-LWJGL "Pixel format not accelerated" crashes)
    • -javaagent:Authlib.jar=http://127.0.0.1:<port> inserted as the first JVM arg when a skin server port exists
    • Optional custom resolution; user JVM args from the profile; executablePath from config.java_path
  • Mod loaders (install_mod_loader, line 414): Fabric & Quilt via their official installer jars (maven.fabricmc.net / maven.quiltmc.org), Forge by unzipping the installer and executing its install-profile processors, NeoForge via --install-client — all run with the bundled Java, 3 retries.
  • Offline-account skin server (_SkinServer, lines 566–890): a complete local Yggdrasil / authlib-injector HTTP server on 127.0.0.1:<ephemeral> implementing / metadata (skinDomains + signaturePublickey), /skin & /cape PNGs, session/minecraft/hasJoined & /profile, and authserver/authenticate|refresh|validate|join. Textures are signed with a per-launch 4096-bit RSA keypair (SHA1withRSA / PKCS1v15) — exactly what authlib-injector expects.
  • Process launch (launch_game, line 1001): clears MC's assets/skins + assets/avatars cache so old accounts can't bleed through; starts Popen with stdout=PIPE, stderr=STDOUT, Windows ABOVE_NORMAL_PRIORITY_CLASS (0x8000) plus an extra SetPriorityClass(ABOVE_NORMAL) boost; streams stdout line-by-line to the UI via on_log; non-daemon thread so log draining finishes with the process; stops the skin server in finally.

⚠ "Hide launcher on game start" is not implemented. The hide_launcher_on_game setting is created, saved and read into settings.hideOnGame — but nothing ever hides or minimizes the window. It is currently inert.

3.3 auth.py (203 lines) — Microsoft OAuth

  • Flow: authorization-code + PKCE (not device-code). CLIENT_ID = "c36a9fb6-4f2a-41ff-90bd-ae7cc92031eb" — Prism Launcher's public Azure client ID (no Azure setup needed). Redirect: http://localhost:9876.
  • Steps: mll.microsoft_account.get_secure_login_data() → local one-shot HTTPServer on port 9876 (validates OAuth state for CSRF) → webbrowser.open(login_url) → wait ≤300 s → complete_login() performs the full internal chain: login.live.com token → Xbox Live user authenticate → XSTS authorize → api.minecraftservices.com/login_with_xbox → entitlements → profile.
  • Refresh: refresh_microsoft_token() wraps mll; triggered before every launch; failures are swallowed so launch continues with the stale token.
  • Skin helpers: _fetch_skin_url() (sessionserver textures property → base64 → skin URL) and fetch_skin_url_by_username() for offline-account previews.
  • No authlib-injector logic here — that lives in game.py (§3.2).

3.4 profiles.py (196 lines) — data model

  • @dataclass Account: id, username, auth_type (microsoft/offline), uuid, access_token, refresh_token, skin_url, skin_path, skin_model (default/slim), cape_path.
  • @dataclass Profile: id, name, version, mod_loader, mod_loader_version, account_id, ram_mb, jvm_args, game_dir, resolution_w/h, fullscreen.
  • ProfileManager persists both to ~/.FractalLauncher/profiles.json with atomic writes (tmp file + os.replace). The loader is schema-tolerant: it filters each entry to the dataclass's known fields, so older files missing new fields load fine (defaults apply) and unknown keys are dropped — that is the entire "migration" system.
  • Offline accounts get a stable fake UUID: uuid3(NAMESPACE_DNS, username), token "offline".
  • Removing an account also removes all profiles bound to it.
  • security Tokens are stored in plaintext — no keyring, no DPAPI, no encryption.

3.5 mods.py (501 lines) — Modrinth-only mod manager

  • API: https://api.modrinth.com/v2 with UA FractalLauncher/1.0 (contact@FractalLauncher.dev), 3× retry with linear backoff. No CurseForge integration and no modpack (.mrpack) support anywhere.
  • Search uses facets (project_type:mod|shader|resourcepack + MC version + loader via _LOADER_MAP); versions endpoint filtered by game_versions/loaders; downloads are streamed 64 KB chunks with progress and partial-file cleanup.
  • Dependency resolver (fetch_mod_dependencies): pulls the latest matching version's dependencies array, keeps required + optional, resolves names via /v2/project/{id}.
  • Update checker (heuristic): derives a slug from the installed filename, compares latest primary file name.
  • Mods live in each profile's own <game_dir>/mods/; enable/disable is a .disabled rename; deletes are path-traversal-guarded (_sanitize_filename + realpath prefix check).

3.6 theme.py (476 lines) + theme.py.backup

  • 20 built-in themes: Lunar (default), Cyber, Forest, Eclipse, Sun, Amber, Nebula, Matrix, Glass, Dark, Ocean, Crimson, Aurora, Grid, Abyss, Green, Pink, Onyx, Ice, Gold.
  • Each theme dict carries both full CustomTkinter keys (BG_DARK, ACCENT, TEXT_PRIMARY…) and an 11-key webview schema (bg, panel, card, accent, tp, ts, tm, ok, warn, err) that maps directly onto CSS custom properties in ui.html.
  • _set_globals(theme) injects a preset into the module's globals (the CTk live-retheme mechanism); _build_ctk_theme(theme) derives a CTk appearance dict at runtime.
  • theme.py.backup is the pre-redesign 7-theme version (Lunar-blue palette, includes the only light theme, "Slate Light"). It is imported nowhere — a dormant snapshot.

3.7 ai_theme.py (455 lines) — Cerebras LLM theme generator

  • A real LLM client, not procedural: POST https://api.cerebras.ai/v1/chat/completions (model discovery via /v1/models). Preferred models: llama3.1-8b → llama-3.3-70b → qwen-3-32b → … with automatic re-resolution and one retry if a model 404s.
  • User types "cyberpunk city at night" → system prompt demands raw JSON of exactly 18 hex keys (CTk schema) or 11 keys (webview schema) → response is fence-tolerant JSON-extracted, validated (^#[0-9a-fA-F]{6}$), missing/invalid keys filled from defaults, saved as "AI: <first 40 chars of prompt>".
  • API key deliberately stored separate from config.json: plaintext ~/.FractalLauncher/cerebras_api_key.txt. Generated themes persist to custom_themes.json / custom_themes_web.json.
  • Spoofs a Chrome User-Agent to bypass Cloudflare bot-blocking on the Cerebras API; explicit error handling for 401 / 403-Cloudflare-1010 / 404 / timeouts.

__init__.py contains only a comment — the package exports nothing; consumers import submodules directly.

Integration details

  • All backend calls go through call('method', …) → await window.pywebview.api.method(...).
  • Python→JS events: listeners for launch_state, console_line, console_clear, install_progress, assets_cache, microsoft_login_success/error, mod_download_progress, mods_list_updated.
  • Bridge-ready lifecycle: pywebviewready handler + a 50 ms poller fallback in case the event fired before listeners attached.
  • SoundFX (lines 799–1008): a full Web Audio API synthesizer for click/pop/nav/launch/success/error sounds, wired to a global click delegation. Secret: press Ctrl+S twice quickly to mute/unmute.
  • Scroll-position saver via MutationObserver that also monkey-patches window.goto.
  • branding bug: <title> and the status bar say "ExtremeLauncher" while i18n strings and the Python window title say FractalLauncher.

4.2 i18n.js (366 lines)

One flat global I18N object, ~175–184 snake_case keys per language, no namespaces/plurals/interpolation. 7 languages: en, fr, es, pt, de, pirate 🏴‍☠️ ("Set Sail!", "Grog Allocation") and darija 🇲🇦 (Moroccan Arabic in Latin script). About 77 keys are actually wired in the HTML; roughly half of each dictionary is unused, and the username key referenced in markup is missing from all seven dictionaries.

SECTION 07

How a launch actually flows

  1. main.py / bootstrap.py write first-run config (bundled java + authlib paths, defaults), then start the pywebview window; on loaded → API.attach(pm, window) prefetches the version manifest (5-min cache).
  2. ui.html fires pywebviewready → loads settings, custom themes, fonts → applies saved theme/language/font → loadHome().
  3. User presses Launch → call('launch') → API.launch() (bridge line 403):
    • re-entrancy guard; profile & account checks;
    • refresh Microsoft token if applicable (result written back via update_account_tokens);
    • push launch_state{launching};
    • resolve the installed version id through a 3-step search (name contains base+loader → exact profile.version → directory scan with inheritsFrom fallback);
    • push assets_cache + start install_progress tracking (sliding-window speed/ETA);
    • if missing: install vanilla (and then the mod loader) with 3× retries;
  4. game.launch_game():
    • clear MC skin/avatar caches;
    • offline account → boot _SkinServer (RSA keypair, health-check), set authlib_base_url = http://127.0.0.1:<port>;
    • build options (Aikar G1GC, authlib agent first, resolution, custom java) → mll.command.get_minecraft_command() → Popen with ABOVE_NORMAL priority;
    • stream stdout line-by-line → console_line events;
  5. On exit: launch_state{stopped, code}; skin server stopped in finally. The UI can re-fetch the whole buffer via get_console_log() or kill a running game via kill_game().

SECTION 10

Notable issues & bugs found

  1. Settings corruption (functional bug). save_settings writes the JS payload verbatim, which uses camelCase keys (javaPath, authlibPath, defaultMcDir, hideOnGame), but every reader expects snake_case (java_path, authlib_injector_path, default_mc_dir, hide_launcher_on_game). After the user saves settings once from the UI, Java/authlib/custom-game-dir preferences silently stop being honored. Additionally, save_settings overwrites config.json wholesale with only the 8 settings keys — wiping pre-existing servers, first_launch, etc.
  2. hideOnGame is inert — saved, read into settings, never used to hide/minimize anything.
  3. launcher/app.py is missing — the CTK fallbacks in main.py, bootstrap.py and pyoxidizer.bzl would crash if reached.
  4. pg-hosting is unreachable — no sidebar item, no goto('hosting').
  5. Branding mismatch — <title> and status bar say "ExtremeLauncher" (and the sidebar logo "EL") while everything else says FractalLauncher.
