LINUX INSTALL GUIDE

Install on Linux.

Everything you need is inside the archive — including its own Java runtime and AuthLib. From Python to first launch in six steps.

WHAT'S IN THE ARCHIVE
FractalLauncher/
├  assets/ — launcher UI files
├  Authlib/ — offline skins & accounts support
├  jdk/ — bundled Java runtime, no system Java needed
├  launcher/ — launcher core
├  bootstrap.py — bootstraps everything on first run
├  main.py · main_webview.py — entry points
├  requirements.txt — Python dependencies
└  run.sh — start the launcher
STEP 01

Install Python and system libraries

Python 3.10+ and pip are required. The launcher's window is rendered through WebKitGTK, so those system libraries go in the same command. Pick your distro:

terminal
sudo apt update && sudo apt install -y python3 python3-pip python3-venv \
  python3-gi python3-gi-cairo gir1.2-gtk-3.0 gir1.2-webkit2-4.1
terminal
sudo dnf install -y python3 python3-pip python3-gobject gtk3 webkit2gtk4.1
terminal
sudo pacman -S --needed python python-pip python-gobject gtk3 webkit2gtk-4.1
STEP 02

Download and extract the archive

Grab FractalLauncher_Linux.zip with the download button at the top of this page, then unzip it anywhere you like — this guide uses ~/FractalLauncher as the example. Adjust every path below to wherever you actually extracted it. Opening a terminal directly inside the extracted folder makes the rest easier:

terminal
cd ~/FractalLauncher
STEP 03

Install the Python dependencies

A virtual environment keeps the launcher's packages separate from your system Python. Create one, activate it, then install everything listed in requirements.txt:

terminal
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

If run.sh already starts the launcher fine in step 04, it handled this for you and you can skip it next time.

STEP 04

Run it with run.sh

Make the script executable once, then start the launcher. Run it from inside the extracted folder so it can find its own files:

terminal
chmod +x run.sh
./run.sh

The first launch takes a little longer while bootstrap.py prepares everything. After that, it's straight in.

Optional — older PCs

Mesa 3.3 override

On older machines — especially ones with Intel iGPUs or aging AMD GPUs — the Mesa driver sometimes reports an OpenGL version below 3.3, which the game needs. If the launcher or the game crashes with GL errors, or the window never renders, prefix the run command with the override so Mesa reports 3.3:

terminal
MESA_GL_VERSION_OVERRIDE=3.3 ./run.sh

This is harmless on modern hardware, so if in doubt, just use it. If it fixes your problem and you want it permanent, open run.sh in a text editor and add this as the first line:

run.sh — first line
export MESA_GL_VERSION_OVERRIDE=3.3

Still failing on very old hardware? Force full CPU rendering instead — slower, but it works almost anywhere:

terminal
LIBGL_ALWAYS_SOFTWARE=1 MESA_GL_VERSION_OVERRIDE=3.3 ./run.sh
STEP 05

Route Java and AuthLib

The archive ships with its own Java runtime and AuthLib — you never install Java yourself, you just tell the launcher where they are. Open Settings in the launcher:

Java Executable — browse to the jdk/ folder inside the extracted directory. This is the Java the game runs on, so pointing it at the bundled one guarantees a compatible version.

example path
~/FractalLauncher/jdk

AuthLib-Injector Path — browse to the Authlib/ folder in the same place. This is what powers offline accounts: skins, capes and account handling all run through it, so leaving it unset means those features stay dark.

example path
~/FractalLauncher/Authlib

Both live side by side inside the folder you extracted — if you moved the folder after extracting, update both paths to match.

STEP 06

Verify with Diagnostics, then launch

Open the Diagnostics panel. It should report that the Java directory is set, that the AuthLib directory is set, that no installed mods are incompatible — plus your OS and allocated RAM. Anything still unset is listed by name. Once everything is green, add an account in Accounts — Microsoft or offline — pick a profile, and press launch.

TROUBLESHOOTING

If something bites.

The script hasn't been marked executable yet. Run chmod +x run.sh once inside the folder, then ./run.sh again. If you copied the folder from a Windows machine, do this after the copy — permissions don't survive it.

Old Intel iGPUs and aging AMD GPUs with Mesa drivers often report an OpenGL version below the 3.3 the game requires. Start the launcher with the override: MESA_GL_VERSION_OVERRIDE=3.3 ./run.sh. If that fixes it, make it permanent by adding export MESA_GL_VERSION_OVERRIDE=3.3 as the first line of run.sh. On very old hardware, force full CPU rendering with LIBGL_ALWAYS_SOFTWARE=1 MESA_GL_VERSION_OVERRIDE=3.3 ./run.sh — slower, but reliable. This is the Linux equivalent of the Mesa3D patch offered for Windows.

The launcher's window renders through WebKitGTK — if those libraries are missing, the window comes up empty. Install them with the command from step 01 (the gir1.2-webkit2-4.1 / webkit2gtk packages), then start the launcher again. If the window renders but the game doesn't, that's the Mesa 3.3 override above.

The dependencies from step 03 aren't installed in the active environment. Re-run pip install -r requirements.txt — and if you use the virtual environment, make sure it's activated first with source .venv/bin/activate.

Open Diagnostics — it names exactly what's wrong: Java directory unset, AuthLib directory unset, or an incompatible mod. Fix what it lists and try again. If a launched game hangs, the Console has a kill-process button to end it cleanly, and every log line copies with one click.

The Java and AuthLib paths you set in Settings point at the old location. Update both — jdk/ and Authlib/ inside the new folder — and check Diagnostics to confirm they're set again.
